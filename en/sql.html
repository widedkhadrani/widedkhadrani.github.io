Database Design and Implementation

Design of a relational database for SnowPeak, a fictional ski resort management company. Data modeling, table creation, SQL queries and process automation using views, triggers and stored procedures.

MySQL SQL Relational Modeling Queries & Automation
01 / CONTEXT

The Project

The project involved designing a database to support the management of a fictional ski resort company, SnowPeak. The system was designed to centralize information about customers, resorts, employees, bookings, lessons, equipment and billing.

The work covered data modeling, database creation and population, followed by the development of queries to retrieve and use the stored information. Advanced SQL features were also implemented to automate certain operations.

14 Relational Tables

Data organized around the main resort management activities, using primary keys, foreign keys and integrity constraints.

3NF Database Structure

The relational model was structured according to the third normal form to reduce data redundancy.

Creating the reservation table SQL · MySQL 
CREATE TABLE IF NOT EXISTS reservation (
    id_reservation INT AUTO_INCREMENT,
    date_debut date NOT NULL,
    date_fin date NOT NULL,
    statut ENUM('En cours', 'Terminée', 'Annulée') NOT NULL DEFAULT 'En cours',
    id_client INT NOT NULL,
    id_station INT NOT NULL,
    CONSTRAINT pk_reservation PRIMARY KEY (id_reservation),
    CONSTRAINT fk_reservation_client FOREIGN KEY (id_client) REFERENCES client (id_client),
    CONSTRAINT fk_reservation_station FOREIGN KEY (id_station) REFERENCES station (id_station),
    CONSTRAINT ck_date_fin CHECK (date_fin > date_debut)
);

03 / DATA QUERIES

Querying and Analyzing Data

SQL queries were developed to retrieve data and provide useful information for business management, including booking tracking, lesson attendance, equipment rentals and resort revenue.

Number of bookings per customer SQL · Joins · Aggregation 
SELECT cl.nom_client, cl.prenom_client, COUNT(r.id_reservation) AS nb_reservations
FROM client cl
LEFT JOIN reservation r ON cl.id_client = r.id_client
GROUP BY cl.id_client
ORDER BY nb_reservations DESC;

Query from 3_BD_advance.sql: it counts the bookings made by each customer and sorts the results in descending order.

Total revenue per resort SQL · Joins · SUM 
SELECT s.nom_station, SUM(fc.montant_total) AS chiffre_affaires_total, COUNT(fc.id_facture_client) AS nb_factures
FROM station s
JOIN reservation r ON s.id_station = r.id_station
JOIN facture_client fc ON r.id_reservation = fc.id_reservation
GROUP BY s.id_station, s.nom_station
ORDER BY chiffre_affaires_total DESC;

Query from 3_BD_advance.sql: it groups invoices by resort and calculates the total amount as well as the number of associated invoices.
