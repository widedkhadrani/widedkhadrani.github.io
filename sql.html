Conception et exploitation d'une base de données

Conception d’une base de données relationnelle pour SnowPeak, une entreprise fictive de gestion de stations de ski. Modélisation des données, création des tables, requêtes SQL et automatisation de traitements à l’aide de vues, de déclencheurs et de procédures stockées.

MySQL SQL Modélisation relationnelle Requêtes & automatisation
01 / CONTEXTE

Le projet

Le projet consistait à concevoir une base de données pour accompagner la gestion d’une entreprise fictive de stations de ski, SnowPeak. Le système devait permettre de centraliser les informations liées aux clients, aux stations, aux employés, aux réservations, aux cours, aux équipements et à la facturation.

Le travail a couvert la modélisation des données, la création et l’alimentation de la base, puis l’écriture de requêtes permettant de consulter et d’exploiter les informations. Des fonctionnalités SQL avancées ont également été développées pour automatiser certaines opérations.

14 tables relationnelles

Organisation des données autour des principales activités de gestion de la station, avec des clés primaires, des clés étrangères et des contraintes d’intégrité.

Base structurée en 3NF

Structuration du modèle relationnel selon la troisième forme normale afin de limiter les redondances.

Création de la table reservation SQL · MySQL 
CREATE TABLE IF NOT EXISTS reservation (
    id_reservation INT AUTO_INCREMENT,
    date_debut date NOT NULL,
    date_fin date NOT NULL,
    statut ENUM('En cours', 'Terminée', 'Annulée') NOT NULL DEFAULT 'En cours',
    id_client INT NOT NULL,
    id_station INT NOT NULL,
    CONSTRAINT pk_reservation PRIMARY KEY (id_reservation),
    CONSTRAINT fk_reservation_client FOREIGN KEY (id_client) REFERENCES client (id_client),
    CONSTRAINT fk_reservation_station FOREIGN KEY (id_station) REFERENCES station (id_station),
    CONSTRAINT ck_date_fin CHECK (date_fin > date_debut)
);

03 / EXPLOITATION

Interrogation et analyse des données

Des requêtes SQL ont été conçues pour consulter les données et produire des informations utiles à la gestion de l’activité : suivi des réservations, fréquentation des cours, locations d’équipements et chiffre d’affaires des stations.

Nombre de réservations par client SQL · Jointure · Agrégation 
SELECT cl.nom_client, cl.prenom_client, COUNT(r.id_reservation) AS nb_reservations
FROM client cl
LEFT JOIN reservation r ON cl.id_client = r.id_client
GROUP BY cl.id_client
ORDER BY nb_reservations DESC;

Requête reprise de 3_BD_advance.sql : elle compte les réservations de chaque client et classe les résultats par ordre décroissant.

Chiffre d'affaires total par station SQL · Jointures · SUM 
SELECT s.nom_station, SUM(fc.montant_total) AS chiffre_affaires_total, COUNT(fc.id_facture_client) AS nb_factures
FROM station s
JOIN reservation r ON s.id_station = r.id_station
JOIN facture_client fc ON r.id_reservation = fc.id_reservation
GROUP BY s.id_station, s.nom_station
ORDER BY chiffre_affaires_total DESC;

Requête reprise de 3_BD_advance.sql : elle regroupe les factures par station et calcule le montant total ainsi que le nombre de factures associées.

Croisement des informations réparties dans plusieurs tables à l’aide de relations entre les identifiants.

Fonctions d’agrégation

-- Places déjà occupées (inscriptions non annulées)
SELECT IFNULL(SUM(nb_participants), 0)
INTO   v_places_prises
FROM   inscription_cours
WHERE  id_cours = p_id_cours
  AND  statut_inscription != 'Annulé';

SET v_places_libres = v_capacite_max - v_places_prises;

IF p_nb_participants > v_places_libres THEN
    SELECT CONCAT('Erreur : seulement ', v_places_libres, ' place(s) disponible(s) dans ce cours.') AS message;
    LEAVE proc;
END IF;

INSERT INTO inscription_cours
    (id_reservation, id_cours, nb_participants, statut_inscription)
VALUES
    (p_id_reservation, p_id_cours, p_nb_participants, 'Confirmé');
